# 施工计划

## 项目目标

做一款以 iPad 为主要练琴设备、兼容 iPhone 的自用钢琴练习工具：读取结构化曲谱，通过 MIDI 或麦克风知道弹了什么，再给出识谱、音高、节奏及按键时长反馈。

项目由 Codex 负责需求细化、实现、自动化测试、代码审查和开发记录。用户需要参与的实际环节是选择 Apple 签名账号、连接自己的琴、确认真实弹奏体验；这些不能通过自动生成代码替代。

## 施工原则

1. 每个阶段交付可运行代码、验证记录和明确的未完成项。
2. MIDI 优先；麦克风单音、双手多音分开验收。
3. 判音使用 MusicXML；按本轮确认需求加入完整公版拜厄 PDF 阅读，PDF 不作为自动判音数据。
4. 同一确定性判定引擎接收 MIDI、屏幕琴键和麦克风事件，避免三套规则。
5. 不因模型生成速度而承诺尚未测试的准确率或日历工期。

## M0 — 工程与可测试核心（本机及远程验收完成）

交付：Swift Package、iOS Xcode 工程、原生共享界面、原创样谱、乐谱解析、练琴状态机、MIDI 解码器、自动化测试。

验收：67 项自动化测试通过；macOS 共享应用编译；三种宽度离屏渲染检查；命名与 Git 基线建立；远程 iOS SDK 构建、iPhone / iPad 各 3 项 UI 场景通过。曲谱范围和硬件未验收项明确，结果见 `STATUS.md`。

## M1 — iPad MIDI 练琴闭环

交付：接入目标钢琴，验证设备连接、重连、双手/分手、和弦、重复键、识谱和节奏模式、一小节预备（4/4 为四拍）、小节循环、完成记录。

验收：在用户目标 iPad 和钢琴上，三首样谱均可完成；人工制造错音、漏音、抢拍、暂停后仍可继续；不发生卡键、游标永久错位或丢失练习记录。反馈延迟实测记录，不预先宣称达标。

前置：完整 Xcode、iOS 平台组件、开发签名、真实 iPad / iPhone 和 MIDI 琴。本机现已安装完整 Xcode，首次组件、签名与真机部署正在配置；上一轮远程 iOS 编译及模拟器交互已通过，M1 真机验收仍需实际连接测试。

## M2 — 日常使用打磨

交付：改进时值与节奏反馈；测试更多 MusicXML 导出来源；导入曲目管理、练习进度恢复、用户可调容错、更多设备及手机窄屏布局。

验收：使用实际练习曲形成回归谱库；导入失败可解释；中途切后台/来电/拔线恢复正确；日常练习不会产生连锁误判。

## M3 — 麦克风单音

本轮提供原型：本地采样、单音音高检测、稳定帧过滤、同一识谱引擎接入，限制 C3–C6。

后续验收：用真实琴逐音录制带真值的样本，覆盖不同力度、距离、房间和设备。统计错判/漏判、同音重击、起音延迟与持续性能，再决定支持音域和明确质量门槛。不能用纯正弦波测试代替实琴验收。

## M4 — 麦克风双手识音

先独立验证已有多音转谱模型在目标设备上的推理速度、音符准确率和谱面约束效果。明确比较单音、多音、踏板、无踏板、安静/噪声场景。验证前不承诺生产可用，也不把单音算法包装成双手陪练。

## 暂不进入首版

账号与云同步、会员支付、课程系统、海量曲库、自动指法教学、出版级打谱、PDF/照片识谱、Android、网页产品及上架营销。

## 2026-11-25 用户确认的首版补充范围

- 采用已确认的米白、墨绿、朱砂 UI 原生开发；曲谱小封面、搜索、收藏、本地封面、详情、练习、真实记录；iPhone 以横屏运行。
- 默认教材目标为拜厄、小汤 1/2/3。已取得的完整资源为公版拜厄 PDF，可离线阅读；上海音乐出版社小汤电子谱与 App 使用权限尚未取得，不以原创样谱或占位卡片冒充。
- 用户 MIDI 线未到，麦克风目标明确为双手和弦。独立接入 Basic Pitch CoreML 多音模型，保留原单音模式；多音为缓冲式实验性识谱，不评节奏/松键时长。自动化推理和合成概率测试只验证实现，不作为实琴准确率验收。
- 验证设备为 iPad 9 / iPadOS 18.0.1、电钢琴扬声器。先完成完整 Xcode、签名、设备安装，再测 A13 上的响应时间、两手和弦、同音重击、踏板、噪声及持续性能。

## 下一次推进顺序

原生 UI 与模型集成验证 → 本机 Xcode 安装/签名/iPad 部署 → 电钢琴麦克风实测 → 根据数据改进多音；MIDI 线到达后继续 M1。上海版小汤完整电子谱仍需可用来源与授权。
